# E. Análisis de los casos 1001/1005 y 1002

## Caso 1001 y 1005: posibles duplicados

La consigna indica que 1001 y 1005 **podrían ser duplicadas**; no afirma que lo sean. La conclusión debe sustentarse comparando:

1. Usuario/solicitante asociado.
2. Servicio solicitado.
3. Tipo de incidencia.
4. Descripción y términos coincidentes.
5. Fecha y hora de creación.
6. Estado actual.
7. Prioridad.
8. Evidencias o referencias asociadas, si existieran en el sistema.

### Información que conservaría

No eliminaría automáticamente una de las solicitudes. Conservaría:

- el identificador original de cada solicitud;
- quién la creó;
- fecha/hora;
- contenido y descripción original;
- estado e historial;
- prioridad;
- relación o referencia de posible duplicidad;
- registros de actualización y auditoría.

Así se mantiene la trazabilidad y se evita perder información útil para una decisión posterior.

## Caso 1002: cambio no autorizado de prioridad

La guía indica:

- solicitud: **1002**;
- prioridad: **Media → Alta**;
- el cambio fue indicado como no autorizado;
- registro de auditoría: **5004**;
- actor: **user_id=9**;
- acción: **CAMBIO_PRIORIDAD**;
- fecha: **2026-09-30 14:32**.

### Cómo relacionar el evento

El registro 5004 debe apuntar a la entidad afectada (Solicitud) y al identificador de la solicitud 1002. Para reconstruir el cambio debe registrar, como mínimo:

- solicitud afectada: 1002;
- actor: user_id=9;
- acción: CAMBIO_PRIORIDAD;
- fecha/hora;
- valor anterior: Media;
- valor nuevo: Alta.

### Cómo investigar si fue autorizado

1. Verificar el rol de `user_id=9`.
2. Revisar si ese rol tenía autorización para modificar prioridades.
3. Buscar una orden, aprobación o evidencia previa que justificara el cambio.
4. Comparar el evento 5004 con los registros de Actualización y Auditoría relacionados con 1002.
5. Revisar si existe otro evento inmediatamente anterior/posterior que explique la modificación.
6. Si no existe autorización ni evidencia válida, conservar el evento como cambio observado/no autorizado para investigación.

No se implementa una base de datos real; se documenta el modelo y el procedimiento conceptual solicitado por el examen.
